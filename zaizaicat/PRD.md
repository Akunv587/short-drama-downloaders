## 1. 项目概述

### 1.1 项目名称

**仔仔猫（ZaizaiCat）**

### 1.2 产品定位

视频数据提取中台，面向短剧运营/推广从业者，提供多平台短剧视频批量下载、元数据提取、音量后处理、短剧库管理等一站式工具。

### 1.3 目标用户

- 短剧推广运营人员
- 需要批量获取短剧视频素材的从业者
- 个人开发者（本项目同时作为求职作品）

### 1.4 运行环境

- **操作系统**：Windows
- **运行形态**：本地 Web 应用（FastAPI 后端 + Alpine.js 前端），浏览器访问
- **分发方式**：开发期用 `start.bat` 启动脚本；发布期用 PyInstaller 打包为 exe

### 1.5 支持平台

| 平台 | 域名 | 访问方式 | 下载技术 |
|------|------|----------|----------|
| TikTok | tiktok.com | 需代理 + Cookie | yt-dlp 子进程 |
| ShortMax | shorttv.live | 需代理 | ffmpeg HLS（页面解析 __NUXT_DATA__） |
| DramaShorts | dramashorts.io | 直连 | ffmpeg HLS（页面解析 __NEXT_DATA__） |

## 2. 全局设计规范

### 2.1 UI 风格

- **主色调**：白色为主，黑灰为辅
- **设计风格**：简约、高级、科技感
- **主题**：支持亮色（默认）/暗色模式切换
- **布局**：左侧边栏导航 + 右侧内容区域

### 2.2 侧边栏导航结构

```
仔仔猫
─────────────
📥 批量下载        ← 功能一
📋 范围下载        ← 功能二
⬇️ 下载中心        ← 统一下载队列/进度
🔊 音量工具        ← 功能三
📊 主页提取        ← 功能四
🔗 剧集提取        ← 功能五
📚 短剧库          ← 功能六
✂️ 文本分段        ← 功能七
─────────────
📁 下载历史
⚙️ 设置
📜 日志
```

### 2.3 全局交互原则

- 用户一般下载 30-80 集的剧，**所有列表页面必须做好滚动**，避免页面过长
- 信息密度高的页面使用**紧凑布局 + 折叠详情**承载
- 关键操作有确认提示，危险操作（删除）二次确认
- 所有长文本输入框支持多行粘贴

## 3. 功能需求

### 3.1 功能一：批量下载

**入口**：侧边栏「📥 批量下载」

**核心流程**：粘贴多个链接 → 提取 → 展示列表 → 选择性下载

**详细交互**：

1. **输入区**：多行文本框，用户粘贴多个视频链接（每行一个）
2. **下载路径选择器**（页面底部）：
   - 显示当前下载路径
   - 「更改」按钮：打开系统文件资源管理器选择目录
   - 「查看」按钮：在资源管理器中打开当前目录
3. **「提取」按钮**：解析所有链接，提取每个链接对应的视频信息
4. **提取结果列表**：
   - 每条展示：剧名 - 剧号（集号）+ 平台标识
   - 每条后附「下载」按钮（单点下载）
   - 顶部附「全部下载」按钮
   - 列表区域可滚动
5. 点击下载后，任务送往「下载中心」执行

**下载路径说明**：下载路径在功能一和功能二的页面底部配置，是每次送往下载中心前必须决定的参数，不放入设置页。

---

### 3.2 功能二：范围下载

**入口**：侧边栏「📋 范围下载」

**核心流程**：粘贴单集链接 → 提取全部剧集 → 文本输入范围 + 列表联动高亮 → 下载选中

**详细交互**：

1. **输入区**：单行文本框，用户粘贴一部剧的某一集链接
2. **下载路径选择器**（页面底部）：同功能一
3. **「提取」按钮**：自动发现该剧全部剧集
4. **提取结果展示**：
   - 顶部显示：剧名 + 总集数
   - 范围输入框：支持以下格式
     - `1-10`（范围）
     - `1 3 5`（离散）
     - `全部`（全选）
     - 组合：`1-3 5 7-10`
   - 「解析」按钮：解析输入范围
5. **列表联动**：
   - 全部剧集以列表展示，可滚动
   - 输入范围并解析后，被选中的剧集**高亮显示**，范围外剧集灰显
   - 底部显示「已选：N 集」
   - 「下载选中」按钮：将选中集数送往下载中心

---

### 3.3 功能三：音量处理工具

**入口**：侧边栏「🔊 音量工具」  
**集成方式**：全局开关（设置页控制），开启后下载完成的视频自动进行音量处理

**独立工具功能**：

1. **批量导入**：用户选择多个视频文件导入
2. **音量处理能力（全功能混音器）**：
   - 响度归一化（EBU R128 两遍法）
   - 手动增益（用户指定 dB，如 +3dB、-5dB）
   - 音量标准化（normalize）
   - 声道平衡
3. **处理参数配置**：每个处理项可选择处理类型和参数
4. **导出**：处理完成后导出到指定目录

**全局开关集成**：

- 设置页有一个总开关
- 开关打开后，所有平台下载完成的视频自动进行响度归一化
- 归一化后的文件替换原文件
- 目标 LUFS 值用户可自定义

---

### 3.4 功能四：主页提取

**入口**：侧边栏「📊 主页提取」

**核心流程**：粘贴 TikTok 主页链接 → 提取所有短剧信息 → 表格展示 + 行内操作 → 导出 CSV

**详细交互**：

1. **输入区**：单行文本框，粘贴 TikTok 主页链接
2. **「提取」按钮**：提取该主页所有短剧信息
3. **提取结果表格**：

| 列 | 说明 | 必要性 |
|----|------|--------|
| 短剧名称 | 剧名 | 必须获取 |
| 播放量 | 播放次数 | 必须获取 |
| 剧集数 | 总集数 | 必须获取 |
| 首集链接 | 第一集的 URL | 尽力获取 |
| 标签 | 短剧标签 | 尽力获取 |
| 发布时间 | 发布日期 | 尽力获取 |

4. **行内操作**：每行后附按钮
   - 「下载」：直接对该剧发起下载（送往下载中心）
   - 「查看详情」：展开该剧详细信息
   - 「加入短剧库」：将该短剧信息写入短剧数据库
5. **导出 CSV**：底部「导出 CSV」按钮，将表格导出为 CSV 文件

**CSV → Excel 小工具（独立面板）**：

- 页面下半部分独立区域，与提取功能解耦
- 用户可上传 CSV 文件或粘贴 CSV 文本
- 「转换为 Excel」按钮：生成 .xlsx 文件并下载
- 该工具可单独使用，不依赖上方的提取功能

### 3.5 功能五：剧集链接提取

**入口**：侧边栏「🔗 剧集提取」

**核心流程**：粘贴单集链接 → 输出全部剧集链接（按顺序排列）→ 多种操作

**详细交互**：

1. **输入区**：单行文本框，粘贴单集链接
2. **「提取」按钮**：自动发现该剧全部剧集链接
3. **提取结果列表**：
   - 按集号顺序排列
   - 每行：第 N 集 + 链接
   - 列表可滚动
4. **操作按钮**：
   - 「复制全部」：复制所有链接到剪贴板
   - 「导出 TXT」：导出为文本文件
   - 「导出 CSV」：导出为 CSV 文件
   - 「发送到批量下载」：将所有链接填入功能一的输入框（页面跳转或自动填充）

**产品定位**：既是独立工具（获取干净链接列表），也是下载的前置步骤（快速衔接下载）。

### 3.6 功能六：短剧数据库

**入口**：侧边栏「📚 短剧库」

**存储方式**：SQLite + 可导出 CSV

#### 3.6.1 数据字段

| 字段 | 说明 |
|------|------|
| 剧名 | 唯一标识，必填 |
| 播放量 | 播放次数 |
| 剧集数 | 总集数 |
| 首集链接 | 第一集 URL |
| 标签 | 标签（JSON 数组） |
| 发布时间 | 发布日期 |
| 来源平台 | tiktok / shortmax / dramashorts |
| 状态 | 已看 / 未看 |
| 备注 | 自由文本 |
| 数据来源 | 手动添加 / CSV导入 / 主页提取导入 / 下载时自动入库 |
| 创建时间 | 入库时间 |
| 更新时间 | 最后修改时间 |

#### 3.6.2 增（入库）

**方式一：手动添加**
- 用户输入一行行剧名（每行一个），直接保存
- 入库时只需剧名，其他字段留空
- 可勾选「是否已看」

**方式二：CSV 导入**
- 用户粘贴 CSV 文本或上传 CSV 文件
- 解析 CSV 中的字段数据
- **智能合并**：如果剧名已存在，其他字段的数据自动对原数据进行补充或覆盖
- 导入时可勾选「是否已看」

**方式三：自动入库（全局开关，默认开）**
- 下载完成时自动将剧名 + 元数据写入数据库
- 标记为「未看」
- 可在设置页关闭

#### 3.6.2 查（查询）

- 列表展示所有短剧，支持滚动
- 搜索：按剧名模糊搜索
- 筛选：按状态（已看/未看）、平台筛选
- 排序：按添加时间、播放量、剧名排序

#### 3.6.3 改（编辑）

- **全字段可编辑**：状态、备注、标签、播放量、剧集数等所有字段都能修改
- 行内编辑或弹窗编辑

#### 3.6.4 删（删除）

- 单条删除（二次确认）
- 批量删除（多选后删除，二次确认）

#### 3.6.5 筛选比对功能

- **输入**：用户批量输入一行行剧名
- **输出**：三态标注表格
  - 每行显示：剧名 / 状态（✅已看 / 📺未看 / ❌数据库中没有）
  - 对数据库中没有的剧名，可一键添加到数据库
  - 已看/未看的剧名都带复制按钮
- 帮用户快速区分哪些已看、哪些未看、哪些是新剧

#### 3.6.6 导出

- 「导出 CSV」按钮：将全部或筛选结果导出为 CSV

### 3.7 功能七：文本分段工具

**入口**：侧边栏「✂️ 文本分段」

**核心流程**：粘贴 N 行文本 → 指定每段行数 → 自动分段 → 多文本框展示 + 复制

**详细交互**：

1. **输入区**：多行文本框，用户粘贴文本
2. **分段配置**：
   - 用户指定「每段行数」（如 30 行）
   - 系统自动计算段数（如 87 行 / 30 = 3 段：30 + 30 + 27）
3. **「分段」按钮**：执行分段
4. **分段结果**：
   - 多个文本框展示，每个文本框显示一段内容
   - 每个文本框上方标注「第 N 段（X 行）」
   - 每个文本框右上角有「复制」按钮，复制该段内容
   - 底部有「下载全部为 TXT」按钮：将所有段合并下载
5. **通用工具**：不限定使用场景

### 3.8 下载中心

**入口**：侧边栏「⬇️ 下载中心」

**定位**：统一管理所有下载任务的执行、进度、状态。功能一/功能二/功能四提交的下载任务都在此执行。

#### 3.8.1 任务列表

每个任务项展示以下信息（紧凑布局 + 折叠详情）：

**概览行（始终可见）**：
- 剧名 + 集号 + 平台标识（图标/文字）
- 状态（等待 / 下载中 / 归一化中 / 重试中 / 成功 / 失败 / 已暂停 / 已取消）
- 进度条（百分比）
- 操作按钮（暂停 / 继续 / 取消 / 立即重试 / 跳过重试）

**折叠详情（展开后可见）**：
- 下载速度 + 已下载大小 / 总大小
- 剩余时间 ETA
- 重试信息（当前轮次 / 3，上次失败原因，下次重试倒计时）
- 文件保存路径（可点击打开文件夹）

#### 3.8.2 下载调度策略

**多平台并行**：
- TikTok、ShortMax、DramaShorts 三个平台的任务可同时执行
- TikTok 任务串行执行（前一条完成或最终失败后才开始下一条），但不影响其他平台的并发下载
- ShortMax / DramaShorts 并发下载，并发数**自适应**：
  - 连续成功则升并发（上限 5）
  - 连续失败则降并发（下限 1）
  - 默认初始并发数 2

#### 3.8.3 重试机制

**自动重试（引擎层）**：
- 单集失败不中断整个任务
- 全部完成后用指数退避重试失败集：5s → 15s → 30s，最多 3 轮
- 分片重试（HLS 分片级别，最多 5 次）

**自动重试展示（前端）**：
- 每个任务项透明展示：当前重试次数（如"重试 2/3"）、上次失败原因、下次重试倒计时
- 用户可手动控制：立即重试 / 跳过重试 / 取消任务

**手动重试（历史记录）**：
- 支持批量重试（多选失败记录一键重试）
- 批量重试时**智能错开重试时间**，避免同时重试多个任务导致被封

#### 3.8.4 任务持久化与恢复

- 任务状态持久化到 SQLite
- 应用重启后，未完成的任务**恢复到队列**：
  - 未开始的任务：恢复为等待状态，自动排队
  - 已开始但未完成的任务：标记为「中断」，需用户手动重试

#### 3.8.5 通知机制

- **页面内 Toast**：右上角弹出短暂提示，自动消失（任务状态变更即时提醒）
- **桌面通知**：调用浏览器 Notification API，关键事件（全部完成、严重失败）即使网页在后台也能弹出系统级通知
- **汇总通知**：批量任务全部完成后发一条汇总（如"金色龙王 50集下载完成，成功48失败2，2条已加入重试队列"）

## 4. 三平台技术方案摘要

### 4.1 DramaShorts

- **前端**：Next.js（React SSR），播放器 Mux Player
- **剧集发现**：抓取页面 HTML → 解析 `__NEXT_DATA__` JSON → `pageProps.episodes` 数组
- **播放地址**：从封面图 URL（`coverUrl`）提取双 hash → 拼接 `cdn.dramashorts.io/video/{hash1}/{hash2}/manifest.m3u8`
- **下载引擎**：HLSEngine 调用 ffmpeg，方案 A（`-c copy`）失败回退方案 B（`-map 0:v? -map 0:a:0?`）
- **认证**：免费内容不需要登录；VIP 内容需 Firebase Auth（预留接口，TODO）
- **网络**：直连即可，不需要代理

### 4.2 ShortMax

- **前端**：Nuxt（Vue SSR），播放器 xgplayer，CDN 走 Akamai
- **剧集发现**：抓取页面 HTML → 解析 `__NUXT_DATA__` JSON 数组（需递归 resolve 引用）→ `shortPlayData.episodeList`
- **播放地址**：`encryptedVideoUrl` 解析 JSON → 按画质优先级 1080→720→480 选取 m3u8
- **下载引擎**：同 DramaShorts（HLSEngine + ffmpeg 两方案回退）
- **认证**：免费内容不需要登录；VIP 内容需 Bearer Token（预留接口，TODO）
- **网络**：国内必须代理，自动检测本地 V2Ray/Clash 端口，注入 HTTP 代理并禁用 HTTP/2

### 4.3 TikTok

- **前端**：无 SSR 数据依赖
- **剧集发现**：TikTokSeriesExtractor → 从页面 `__UNIVERSAL_DATA_FOR_REHYDRATION__` JSON 递归搜索 `dramaID` → 调用内部 API `/api/drama/episode/item_list/?aid=1988&dramaID=xxx&count=200` 分页拉取。回落方案：从页面内嵌 JSON 收集 `/video/{id}` 链接
- **下载引擎**：yt-dlp 子进程（asyncio.create_subprocess_exec）
- **认证**：Cookie 机制（cookies.txt 或 CDP 连接 Chrome 提取）
- **网络**：必须代理
- **反爬多级回退**：
  - 第一级：API 策略回退（默认 → api=web → api=mobile）
  - 第二级：203009 错误时轮换 app_info（trill / musical_ly）
  - 第三级：Unexpected response 时 CDP 刷新 Chrome Cookie 后重试
- **反反爬措施**：重试 5 次、分片重试 5 次、请求间隔 3-5 秒随机延迟、Chrome 指纹伪装
- **Cookie 失效处理**：通过 CDP 连接 Chrome，若 Chrome 有有效登录态则自动刷新 Cookie 重试，失败才提示用户

### 4.4 共通机制

- **统一入口**：`download_engine.py` 的 `execute_download` 函数，按 `detect_platform(url)` 分流
- **容错框架**：单集失败不中断；全部完成后指数退避重试；支持暂停/取消检查点；多链接去重
- **响度归一化**：下载完成后统一经过 LoudnormProcessor 的 EBU R128 两遍法（可通过配置开关）
- **文件保护**：Windows 文件句柄延迟释放保护的指数退避重试
